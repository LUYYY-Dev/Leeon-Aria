## 命题

搭建个人博客时，是**直接套用成熟主题**，还是**自己写一套**？

直觉答案是前者：成熟主题经过大量用户验证，功能齐全，省时间。

这个直觉错在哪？我们把推理过程完整写下来。

## 第一步：把模糊的选项变成可比较的维度

"哪个更好"是无法回答的问题，必须先拆成维度。

| 维度 | 说明 |
| --- | --- |
| 上手成本 | 从零到第一篇文章发布需要多久 |
| 维护成本 | 一年后大概率会坏掉吗 |
| 定制能力 | 想改首页时阻力有多大 |
| 依赖数量 | 构建链里有多少会过期的东西 |

关键是：**对我们是重要的维度，未必是社区默认的维度。**

## 第二步：给维度加上权重

我们是非全职维护者，博客是长期项目而不是一次性交付。所以：

- 维护成本 ≫ 上手成本
- 定制能力 > 功能数量

一句话：**三年后它还能一条命令构建出来，比今天多十个功能重要得多。**

## 第三步：回到事实

成熟主题（以我们考察的 Blowfish v3 为例）的 `package.json` 里是这样的：

```json
{
  "scripts": {
    "build": "NODE_ENV=production npx @tailwindcss/cli -c ./tailwind.config.js -i ./assets/css/main.css -o ./assets/css/compiled/main.css --jit",
    "postinstall": "vendor-copy"
  },
  "devDependencies": {
    "@tailwindcss/cli": "^4.3.3",
    "tailwindcss": "^4.3.3",
    "vendor-copy": "^3.0.1"
  }
}
```

这意味着构建链里多出了：Node 运行时、npm 依赖树、Tailwind 版本、以及一个 `postinstall` 钩子。

**每一个都是一年后可能失效的环节。**

## 第四步：推演，而不是猜

假设一年后 Tailwind 发布 v5，改了配置格式：

- 套用主题：需要读懂它的构建配置，升级、测试、可能还要改主题源码
- 自建主题：完全不受影响，因为根本没有这条依赖

再假设我们想加一个"首页粒子动画"：

- 套用主题：需要覆盖它的首页模板，同时不破坏它原有的样式体系
- 自建主题：直接写

**两件事都指向同一个结论。**

## 结论

我们选择了自建主题，代价是：

- 放弃了现成的一百多个功能
- 前两个小时的工作量大约是套用主题的三倍

换来的是一条只有 Hugo 二进制、没有任何第三方依赖的构建链。

> 真正的成本从来不是"当下多花了多少时间"，而是"未来被迫回来处理它的概率"。

## 什么情况下我们的结论会反转

诚实地说，如果满足以下任一条，我们**会**选择现成主题：

1. 博客是副业里的一次性展示，不打算长期更新
2. 团队里已经有人熟悉那套构建链
3. 需要的功能非常特定（例如文档站的多版本管理），自建成本远高于定制成本

结论永远带边界，脱离边界谈结论没有意义。
